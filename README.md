# demo-app

Backend service generated by `backend-cli`. It ships with working authentication, a sample CRUD resource, and the production-hardening basics (CORS allowlist, Winston logging, rate limiting, Docker) — treat it as a starting point, not a finished product.

## Stack

| | |
|---|---|
| Language | TypeScript |
| Framework | Express |
| Database | MongoDB |
| ORM/ODM | Mongoose |
| Auth | JWT |
| Validation | Zod |
| API docs | Swagger |
| Logger | Winston |
| Testing | Jest |
| Docker | Yes |
| Metrics | Prometheus (`prom-client`) + Grafana |

## Prerequisites

- Node.js 20+
- npm
- A running MongoDB instance (or use `docker compose up` — see Docker below)

## Getting started

```bash
cp .env.example .env   # already generated for you with local defaults — review before deploying
npm install
npm run dev
curl http://localhost:3000/health
```

## Environment variables

Set in `.env` (a working `.env` with local defaults is generated for you; `.env.example` documents the shape without secrets and should be the one committed to git).

| Variable | Purpose |
|---|---|
| `APP_NAME` | Service name, used in logs and Swagger title. |
| `APP_HOST` | Host the server binds to (default 0.0.0.0). |
| `PORT` | Port the server listens on (default 3000). |
| `NODE_ENV` | development, production, or test. |
| `MONGODB_URI` | Connection string for MongoDB. |
| `JWT_SECRET` | Secret used to sign/verify access tokens. MUST be changed in production. |
| `CORS_ORIGIN` | Comma-separated list of allowed origins, e.g. https://app.example.com,https://admin.example.com. |

## API endpoints

- `GET /health` — health check, no auth required.
- `POST /auth/register` — create an account. Body: `{ email, password }`. Returns a bearer token.
- `POST /auth/login` — authenticate. Body: `{ email, password }`. Returns a bearer token.
- `GET /items` — list items. **Requires** `Authorization: Bearer <token>`.
- `POST /items` — create an item. Body: `{ name, description?, price }`. **Requires auth.**
- `GET /items/:id` — fetch one item. **Requires auth.**
- `PUT /items/:id` — partially update an item. Body: any subset of `{ name, description, price }`. **Requires auth.**
- `DELETE /items/:id` — delete an item. **Requires auth.**
- `GET /docs` — Swagger UI (generated from JSDoc comments in `src/docs/`).
- `GET /metrics` — Prometheus metrics (default Node.js/process metrics plus HTTP request duration/count), no auth required.

```bash
# Example: register, then use the token to create an item
curl -X POST localhost:3000/auth/register -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"password123"}'

curl -X POST localhost:3000/items -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <token from above>' \
  -d '{"name":"Widget","price":9.99}'
```

## Project structure

```
src/
  app.ts            — Express app: middleware, CORS/helmet/rate-limit, routes, error handling
  server.ts         — process entry point: connects the DB, starts listening, graceful shutdown
  routes/               — Express routers (health, auth, items, metrics)
  controllers/          — request handlers
  models/               — ORM-agnostic data access (same function names regardless of ORM chosen)
  middlewares/          — error handling, 404s, request validation, auth guard, metrics tracking
  schemas/               — request validation schemas
  docs/                  — JSDoc/@swagger annotations for Swagger UI
  metrics/               — Prometheus registry and custom HTTP metrics (prom-client)
  tests/                 — Jest tests
packages/
  config/                — env-driven app config (port, DB, JWT, CORS)
  constants/             — shared string/number constants (HTTP status, pagination, regex, rate limits)
  handlers/              — successHandler/errorHandler response envelope
  utils/                 — logger, payload helpers
  database/              — DB connection manager (Mongoose)
monitoring/
  prometheus.yml         — Prometheus scrape config (targets the API's /metrics)
  grafana/provisioning/  — auto-provisioned Grafana datasource + starter dashboard
```

## Docker

```bash
docker compose up --build   # runs the API, MongoDB, Prometheus, and Grafana
```

The API container reads its config from `.env` (via `env_file` in `docker-compose.yml`). The bundled database service is for local development only.

## Monitoring

`docker compose up` also starts:

- **Prometheus** at http://localhost:9090 — scrapes the API's `/metrics` endpoint every 15s (see `monitoring/prometheus.yml`).
- **Grafana** at http://localhost:3001 — login `admin` / `admin` (change this before deploying; set via `GF_SECURITY_ADMIN_PASSWORD` in `docker-compose.yml`). Comes pre-provisioned with a Prometheus datasource and an "API overview" dashboard (request rate, p95 latency, 5xx error rate, process memory, event loop lag).

Running the API outside Docker (`npm run dev`)? Point Prometheus at `localhost:3000` instead by editing `monitoring/prometheus.yml`.

## Security checklist before deploying

- [ ] Replace `JWT_SECRET` with a strong, unique secret (not the `change_me` default).
- [ ] Set `CORS_ORIGIN` to your real frontend origin(s) — do not leave it as `localhost`.
- [ ] Point `NODE_ENV=production` and use a managed/production database, not the Docker Compose one.
- [ ] Put this service behind HTTPS (a reverse proxy or platform load balancer, not in-process).
- [ ] Change the Grafana admin password (`GF_SECURITY_ADMIN_PASSWORD` in `docker-compose.yml`) and restrict access to `/metrics`, `:9090` (Prometheus), and `:3001` (Grafana) at the network level.
